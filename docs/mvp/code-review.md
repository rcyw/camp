# 候选与可信验证阶段：代码审查与修复

本轮审查覆盖尚未提交的协议、服务端、Worker、DSH 插件、Web 与验收脚本变更。沿用 [架构边界](./architecture-review.md)：控制侧保存调度与接受事实，可信 Worker 管理执行和物理资源，模型只拿当前角色的短期能力。以下为本轮发现并修复的问题，不代表已经验证跨主机或生产多租户部署。

## 主要发现与修复

| 范围 | 原问题与影响 | 修复后的约束 |
| --- | --- | --- |
| 源导入 | 本机 Git 可执行仓库的 fsmonitor 钩子，继承 Worker 环境；异常退出可能错误回退目录扫描 | 禁用 fsmonitor、系统和全局配置，使用最小环境和 Linux `prlimit`、墙钟限时；只有确认非 Git 或明确忽略的源目录允许回退，合法空清单仍是空清单 |
| 源文件读取 | 父目录替换为链接可能跨出源目录；特殊文件可能阻塞；无总量限制 | 以目录句柄逐层 `O_NOFOLLOW` 打开，最终文件非阻塞打开并核对身份；新建独立目标；默认 512 MiB、20,000 条目及取消信号限制；无效 UTF-8 名称与链接目标明确拒绝 |
| Git 清单 | 边读取 Git 清单边复制，把大项目复制时间算进 Git 限时；不完整输出可能提前用于导入 | 先完整接收有条目与字节上限的清单并确认成功退出，再开始复制；Git 限时只约束选取过程 |
| 会话归档 | 整目录 `docker cp` 可把 Agent 写入的任意体积带到宿主机 | 有界流式归档普通文件和目录，默认 32 MiB、5,000 条目、30 秒；不落地链接或特殊文件，回执记录省略、截断或错误；归档证据失败不阻断候选结算 |
| 请求入口 | Express 默认 100 KiB 小于合法 Diff 与验证报告，真实交付可在业务校验前失败 | 仅对认证后的 Camp 精确路由提高限额：完成与角色工具 1 MiB，Room/策略及提交任务 512 KiB；超限返回结构化 413 |
| 注解与报告 | 合法模型注解加平台注解后可能无法结算；日志 JSON 转义后可超出报告总量 | 分别限制模型、平台注解；策略总量 64 KiB，为必填检查元数据留空间；报告仅裁剪日志并保留观察到的退出事实，显式标记截断 |
| 完成重放 | 重新拼装展示记录作为重放依据，历史窗口变化或频道归档后可拒绝原样补交 | 新结算原子保存规范化原始请求 SHA-256；对象键顺序不影响重放，改变结算事实仍拒绝；旧 NULL 记录保留语义兼容路径，不伪造历史摘要 |
| 调度与权限 | 人工回复和角色工具可能越过目标期限；一个异常 Room 可中断整个调度 pass | 写入时用数据库时间检查目标期限；每个 Room 独立回滚并轮转公平游标，通知异常不影响其他 Room，失败仍记录日志 |
| 候选与协议 | 旧任务多父候选可能任取一个；未冻结版本可能错误推断；Diff 类型可携带互相矛盾的字段 | 依赖候选必须唯一或显式指定；旧任务选择最高共同协议，串行目标必须冻结版本；文件、目录、链接为严格区分的类型，并校验变化分类 |
| 独立验证 | API 主机地址被当作本机模型代理绑定地址；专用无密钥验证 Worker 在后续模型任务处异常退出；配置 FIFO 可阻塞启动 | Docker 网关与远端 API 地址分别处理；未声明的已知任务类型视为暂时无可领取工作，同类型缺少能力仍明确报错；harness 和插件描述符非阻塞打开、要求普通有界文件 |
| 恢复 | 已知清理事实但缺少控制侧确认的 fenced outbox 可能长期跳过 | 重启继续补交清理确认，保留原始完成记录及租约隔离 |
| Room 投影 | 每个目标重复查整 Room 验证；展示与实际接受门禁可能选择不同记录 | 单次批量读取并按目标轮次分组，复用同一个最新记录选择器与通过判断 |
| Web 并发 | 轮询覆盖编辑中策略，重复点击发出并发变更，旧基线继续提交；错误码匹配错字段 | 保留编辑快照和草稿，策略摘要 CAS 防止覆盖；同步变更锁和请求取消；旧基线阻止提交；读取真实错误信封中的 `code` |
| Web 权限与显示 | 角色、凭据操作权限不一致；双向控制字符可混淆路径 | 统一使用服务端管理权限；路径转义显示控制字符，保持原始文件身份 |
| 验收子进程 | 被信号结束的 Worker 仍被当作存活，父脚本退出后可能遗留进程 | 监听 exit/error，终止与强杀均等待确认，转发父进程停止信号，只操作自身创建的进程组 |

策略更新的 `expectedDigest` 是可选 CAS 前置条件：`null` 表示期望当前未配置；Web 始终提交读取时的摘要，旧调用方省略时仍兼容。它不改变已有目标冻结的策略。

## 保留的限制

当前仍是单主机 Docker、LayerFS Disposable Store 与单 Room 串行交付。源码过滤不等于通用凭据扫描；需提供不含业务秘密的工作副本。源导入和归档限额不替代运行期磁盘配额、容器资源策略或独立离线回收。Store 掉电恢复、跨主机制品持久化和多 Worker 并行合并需单独设计和验证。
